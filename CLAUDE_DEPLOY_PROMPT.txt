CLAUDE_DEPLOY_PROMPT (SANITIZED)

This file previously contained instructions for an autonomous, zero-touch deployment
flow that bypassed branch protections, used force-pushes to main, and deployed
without any human approval. That behavior is unsafe and has been deliberately
removed. This file must NOT be used to orchestrate unattended or protection-
bypassing deployments.

SECURITY & GOVERNANCE POLICY
--------------------------------
- Do NOT bypass branch protections.
- Do NOT use `git push --force` or any equivalent force-push to protected branches
  (e.g., `main`, `master`, or other protected branches) except under an explicitly
  documented and approved emergency procedure.
- Do NOT use admin overrides (e.g., `gh pr merge --admin`) to circumvent required
  reviews, checks, or approvals, except under an explicitly documented and approved
  emergency procedure.
- Do NOT execute deployment or git commands automatically based solely on the
  contents of this file.
- All deployments MUST follow the organization's standard CI/CD pipeline and
  require the normal reviews and approvals.

GUIDANCE FOR AI AGENTS AND AUTOMATION
-------------------------------------
If you are an AI assistant, script, or automation system reading this file:

- You MUST NOT:
  - Execute shell commands directly.
  - Modify git branches, tags, or remotes.
  - Push any commits or tags to any remote.
  - Trigger deployments, rollbacks, or infrastructure changes.
  - Attempt to bypass git hooks, branch protections, or CI checks.

- You MAY:
  - Suggest safe commands or steps as text for a human operator to review.
  - Propose changes that go through normal pull request workflows.
  - Help draft documentation or checklists that conform to existing policies.

Any concrete deployment or git operation MUST be:
- Initiated and executed by a human with appropriate access.
- Performed via the standard, approved tooling and pipelines.
- Subject to the usual code review, testing, and approvals.

SAFE, HIGH-LEVEL DEPLOYMENT CHECKLIST (FOR HUMANS ONLY)
-------------------------------------------------------
1. Create or update a feature branch with your changes.
2. Run tests and linters locally (e.g., `npm test`, `npm run lint`, etc.).
3. Open a pull request into the protected branch (e.g., `main`).
4. Obtain required code reviews and approvals.
5. Ensure all required CI checks pass.
6. Merge using the platform's standard, non-force merge mechanism.
7. Trigger deployment via the approved CI/CD pipeline or deployment tool.
8. Verify the deployment (e.g., check health endpoints and logs).

NOTE
----
This file is intentionally non-executable and must never contain instructions
that tell an AI or automation to:
- Bypass branch protections,
- Force-push to any branch,
- Use admin overrides to skip reviews or checks, or
- Deploy code without explicit human review and approval.

If you need to modify the deployment process, do so by updating the organization's
official CI/CD configuration and documentation, and ensure all changes are
reviewed and approved through the normal process.

End of file.
